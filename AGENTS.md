# Игра «Закрытая выставка. 1898»
Образовательная браузерная игра-квест для студентов НЭТИ (задание А.К. Кириллова).
ЦЕЛЬ: красотой картин эпохи передвижников познакомить с сознанием людей эпохи великих реформ
и подтолкнуть задуматься, почему русское общество XIX века воспринимало Ивана IV как злодея.
СЮЖЕТ: игрок — корреспондент иллюстрированного журнала 1898 г. в закрытой частной галерее.
Решённые задания открывают двери в новые залы (часть залов — изолированные ветки).

## Жёсткие требования
1. Стек: Vite + TypeScript + Three.js (единственная тяжёлая зависимость, версия фиксируется).
   Залы — 3D-галерея от первого лица на WebGL; задания, «Разворот», книги и финал — обычные
   HTML-оверлеи поверх 3D. Должно идти на среднем офисном ноутбуке со встроенной графикой
   (≥30 fps): низкополигональная геометрия из примитивов, без внешних 3D-моделей, ≤4 источника
   света на зал, без теней, mipmaps, загрузка по залам и dispose() при выходе. Разрешение и
   размеры уровней текстур регулируются разделом «Чёткость, стиль, управление, двери» ниже.
   Сборка — статический dist/; бэкенд только PHP 8.
2. Интерфейс на русском. В UI ЗАПРЕЩЕНЫ слова-указания: «нажми», «кликни», «пойди»,
   «прочитай», «перетащи», «выбери». Игрок догадывается по среде: курсор-рука, подсветка
   при наведении, торчащие закладки в книгах, записки и письма 1890-х (повествовательные,
   не приказные). Тон — письма и газета 1890-х.
3. Это НЕ тест: никаких экранов «вопрос + варианты + верно/неверно». Обратная связь —
   через мир (щёлкнул замок, открылась дверь, пластинка легла в конверт).
4. Связь «картина ↔ текст»: рядом с картиной всегда её «книга-источник». Режим «Разворот»:
   слева картина с подписью, справа книга, открытая на нужном абзаце; можно листать
   вперёд и назад и читать весь текст главы.
5. Подсказки только по желанию игрока, 3 уровня: намёк → в какой книге → какой фрагмент.
6. Баллы: база 100 за задание; −10 за неверную попытку (минимум 20); подсказка 1 = −25%,
   2 = −40%, 3 = −50% от базы (в шахматах подсказка 1 = −50%). Топ-20 рекордов виден всем.
7. Все данные — JSON в /src/data (halls, paintings, links, tasks, hints, zones, audio,
   libretto-lines) и /src/data/texts (книги по главам): преподаватель правит без кода.
8. Тексты НЕ грузятся целиком: книги режутся на главы/разделы, главы подгружаются лениво.
   Данные, грузимые при старте, ≤ 300 КБ. В публичную сборку входят только главы,
   нужные для links.json и заданий.
9. Доступность: Tab/Enter для всех интерактивных объектов, alt-тексты, адаптив
   десктоп/планшет.
10. Звук: ровно три записи в public/assets/audio: boris.mp3 (Мусоргский, «Борис Годунов»,
    фрагмент про Казань), oprichnik.mp3 (Чайковский, «Опричник»), kalashnikov.mp3
    (Рубинштейн, «Купец Калашников»); описание в src/data/audio.json. Автовоспроизведения нет,
    preload="none". Если файла нет или воспроизведение заблокировано — задание работает в
    текстовом режиме (субтитры строк либретто), ошибок в консоли нет.
11. Никаких выдуманных цитат: каждая цитата обязана быть дословной подстрокой абзаца;
    это проверяет tools/validate-all.ts (npm run validate).
12. 3D-управление: WASD/стрелки + мышь (pointer lock по клику, Esc выходит); запасное —
    перемещение по меткам на полу кликом/тапом; Tab переключает интерактивные объекты,
    Enter открывает; простые коллизии по AABB. Интерактивные объекты (картина, пюпитр,
    пластинка, дверь, шахматный столик) подсвечиваются при наведении; курсор-рука; без
    текстовых указаний на действие.
13. Запасной режим: без WebGL — список залов с кнопками-дверями, логика та же.

## Чёткость, стиль, управление, двери

Эти требования заменяют конфликтующие ограничения этого файла и применяются после требований
высшего уровня: корректность управления, целая геометрия проёмов и дверей, чёткость текста и
изображений, производительность, затем декор.

### Текст и чёткость
- Весь нужный игроку текст рендерится HTML/CSS поверх canvas. Текстуры WebGL с буквами — только
  необязательный декор, они не сообщают сведения, необходимые для игры.
- Используй локальные шрифты с засечками в WOFF2, `font-display: swap` и preload. Основной текст
  — не менее 18 px, книга — 19–20 px, межстрочный интервал 1.5, контраст не ниже 7:1. Под текстом
  непрозрачный фон либо затемнение не меньше 85%; без blur/backdrop-filter и CSS scale текста.
  Применяй `text-rendering: optimizeLegibility` и `-webkit-font-smoothing: antialiased`.
- Настройки содержат ползунок размера текста 100–150%, сохраняемый в localStorage.
- Canvas использует antialias и pixelRatio до 2 с ResizeObserver и размером буфера canvas,
  согласованным с CSS-размером и DPR. Автоадаптация при FPS ниже 30: сначала 1.5, затем 1;
  повышай качество обратно только при стабильных 55 FPS. В меню есть настройка качества.
- Подписи картин — HTML-карточки не меньше 18 px, видимые при наведении/прицеле или расстоянии
  менее 3 м; их экранная позиция вычисляется проекцией точки 3D. Не масштабируй текст transform.
  Информационные подписи в текстурах 3D-зала запрещены; таблички служат декором.
- Для изображений используй sRGB, mipmaps, `LinearMipmapLinearFilter`, максимальную доступную
  anisotropy. Сразу загружай thumb около 400 px, затем medium 1024 px; при расстоянии менее
  2.5 м загружай large 2048 px или оригинал меньшего размера. Выгружай крупные уровни при
  удалении, держи не более шести 2048 px текстур и освобождай их через LRU/dispose.
- `public/assets/paintings` пересобирай из презентаций в размерах original до 3000 px, thumb 400,
  medium 1024, large 2048 (предпочтительно WebP quality 90–92, JPG fallback). Общий вес не более
  60 МБ; если превышен — quality 88 для файлов тяжелее 1 МБ. В «Развороте» загружай large/original;
  зум изображения не меняет масштаб текста, а при увеличении >1.5 подгружает original.

### Стиль и производительность
- Галерея — частное собрание мецената 1890-х в историзме русского стиля: тёмное дерево, бархат,
  латунь, лепнина, расписные своды, тёплое вечернее освещение и глубокие угловые тени. Без
  мультяшности и неона.
- Лимит кадра — 200 draw calls и 250k треугольников; декоративные текстуры — до 1024 px и до
  4 МБ на зал; сборка без изображений и аудио — до 25 МБ; встроенная графика — не ниже 30 FPS,
  headless medium — не ниже 45 FPS.
- Применяй sRGB и ACESFilmic, лёгкий тёплый fog и окружение через PMREM/RoomEnvironment для
  отражений. Реальных теней нет; запечённые градиенты дают пятна света, затемнение углов и
  стыков и AO. До трёх PointLight на зал; у рам — латунные лампы и мягкие световые пятна.
  Пылинок Points — не более 150. Замерь первые 3 с: low убирает пыль/лучи и уменьшает декор
  до 512 px; low/medium/high и настройка качества доступны игроку.
- Повторяющиеся детали делай InstancedMesh или объединённой геометрией. Залы должны быть
  узнаваемо разными: панели, орнамент, ниши и портьеры, лепной карниз, потолочная розетка,
  фактурный паркет/мрамор, ковры, мебель и предметы соответствующей теме. Процедурные карты
  кэшируй и освобождай при выходе. Внешние CC0-текстуры допустимы только с записью лицензии в
  CREDITS.md.

### Управление и взаимодействие
- Источник направления — только yaw/pitch в радианах. Камера в корне сцены, rotation.order=`YXZ`,
  rotation.y=yaw, rotation.x=pitch, rotation.z=0. При yaw=0 взгляд идёт в -Z. На полу:
  forward=(-sin(yaw),0,-cos(yaw)), right=(cos(yaw),0,-sin(yaw)); движение — их взвешенная
  сумма, нормализованная до скорости. Проверяй совпадение forward с горизонтальной проекцией
  `camera.getWorldDirection()` (dot ≥0.999). Залы не поворачивают систему координат игрока.
- Клавиатуру читай по `event.code`, не `event.key`: KeyW/A/S/D и стрелки, Shift для бега,
  KeyE/Space/Enter — взаимодействие. Обработанные клавиши preventDefault; повторы игнорируются,
  противоположные направления гасятся. Set очищается при blur, скрытии вкладки, потере pointer
  lock и открытии оверлея. Не обрабатывай движение в input/textarea/select/contenteditable.
- Время кадра clamp 0–0.05 с. Скорости: ходьба 2.2 м/с, бег 3.6 м/с; разгон 0.12 с, торможение
  0.10 с; диагональ не быстрее прямой; pitch не влияет, высота глаз постоянна 1.6 м. Покачивание
  камеры выключено по умолчанию и настраивается.
- Мышь: yaw -= movementX × чувствительность, pitch -= movementY × чувствительность, базовая
  чувствительность 0.0022 rad/px, диапазон настройки 0.5–2.0, pitch ±85°, roll 0. Игнорируй
  события со скачком свыше 200 px. При клике захватывай pointer lock; если он недоступен или
  отклонён, зажатая левая кнопка вращает камеру. При открытии оверлея освобождай lock, при
  закрытии восстанавливай, если он был. Меню содержит чувствительность и инверсию вертикали.
- Игрок — круг радиусом 0.3 м; стены/мебель — AABB, колонны — круговые коллайдеры. Разрешай
  движение по осям со скольжением; шаг интеграции не более 0.1 м. Не допускай выхода наружу,
  туннелирования и застревания. Закрытая створка блокирует проход, открытая — нет. Переход между
  залами непрерывен, без телепорта, с сохранением yaw.
- Raycaster работает из центра в pointer lock и от курсора вне него; дальность 3 м. Hover
  подсвечивает объект за один кадр, курсор — рука. Клик/KeyE/Enter/Space открывают объект.
  Tab и Shift+Tab циклят интерактивные объекты по расстоянию, подсветка и поворот к выбранному
  объекту занимают до 0.3 с. На сенсорном устройстве показывай виртуальный джойстик слева и
  обзор правой половиной экрана; метки пола позволяют плавно двигаться с коллизиями.
- Показывай компас в `?dev=1`: направление взгляда/движения, координаты и yaw. Управление
  обновляется только в requestAnimationFrame; ставь его на паузу при потере фокуса/visibility.
  Слушатели имеют единые init/destroy и снимаются при выгрузке зала. Настройки содержат качание,
  бег, качество, звук и размер текста.

### Двери и проверка
- Проём вырезается стеной, а не закрывается плоскостью. Стена толщиной 0.45 м собирается из
  левой/правой частей и перемычки; ширина прохода 1.9 м, высота 3.0 м. `doorShape` в halls.json:
  rect или arch (прямоугольник 2.5 м плюс полукруг радиуса 0.95 м). Добавь боковые/верхние откосы,
  латунный порог 0.01 м, архитектрав с профилем ExtrudeGeometry по обеим сторонам, сандрик,
  дверную коробку 0.06×0.12 м. Все слои разнесены не менее чем на 0.002 м.
- Двустворчатые объёмные двери: створки 0.92×2.9×0.06 м, низ на высоте 0.02 м, 3–4 рельефные
  филёнки, багет, латунные ручки/замочная накладка и скважина. Створки на pivot у внешней петли;
  открываются внутрь следующего зала на 100° за 1.2 с easing. Сначала 0.25 с щелчок замка,
  поворот накладки и короткий синтезированный звук. У закрытой двери нет текста-подсказки.
- Цвет/стиль двери и формы задаются в halls.json (`doorStyle`: oak/ebony/gilded/plain;
  `doorShape`: rect/arch). Дерево лакированное (roughness .45, envMap), латунь metalness .9,
  roughness .3; арочный проём имеет фрамугу с матовым слабосветящимся стеклом. Коробка и откосы
  не дают просветов; в открытом положении створки не мешают коллайдерам, а из порога виден зал.
- Для контроля добавляй Vitest/Playwright-тесты осей при 8 yaw, движения/проекций, мыши, разных
  раскладок, диагонали, blur/оверлеев, dt и fps, стен/дверных коллизий и геометрии створок.
  Держи в `tools/shots` 3 скриншота каждого зала, contact sheet, состояния дверей и sharpness
  экранов. В REPORT.md фиксируй причины проблем, pass/fail чеклист, вывод/шрифт/контраст,
  текст в текстурах с обоснованием, renderer.info на зал и вес сборки.

## Каталог заданий
- memo: 12 карточек (6 пар), лимит 30 ходов, одинаковое соотношение сторон (crop/pad).
- puzzle: мозаика 4×3, перетаскивание, без таймера.
- match-captions: картины ↔ подписи (автор. название. год), перетаскивание.
- crossword-names: подсказки — картины; слова: Грозный (раскрыто), Колычёв, Онуфревна,
  Салос, Морозов, Фёдоров.
- crossword-authors: подсказки — вырезки картин; слова: Пукирев (раскрыто), Неврев,
  Новоскольцев, Рябушкин, Мясоедов, Маковский, Лебедев, Нестеров.
- fill-words-repnin: стихотворение А.К. Толстого с пропусками: хоровод, окружил, плясать,
  раб, день, встарь, час, пал (поле ограничено числом букв, е=ё).
- fill-words-monument: три имени с контурами букв (Сильвестр, Анастасия, Адашев), рядом
  воспоминания Микешина и описание памятника Тысячелетию России.
- split-names: три области «картины + имя»; дано Островский; закрыты звёздочками Карамзин,
  Толстой.
- drag-crown: корона на картину Неврева «Опричники» (верная зона — polygon из zones.json);
  рядом четверостишие-подсказка; нужно вспомнить у Карамзина убийство боярина Фёдорова.
- drag-figure: две почти одинаковые картины (подлинник/копия), фигурка ставится в
  пустой слот; на неподходящую картину поставить нельзя (возвращается).
- combo-lock: три окошка-карусели картин без подписей; верно, когда во всех трёх картины
  про Николу Салоса (Геллер; Пелевин; Мясоедов); рядом отрывок Карамзина про подвиг Салоса.
- chess: FEN 2bq2nr/k5pp/p2Np3/1p2P3/5P1B/NQP4P/P5P1/6KR b - - 0 1;
  верные ходы Qd8-b6, Bh4-f2, Qb6xf2, Kg1xf2; 4 строки записи; режим select как запасной.
  Источник: эпизод партии царя с Бельским в «Смерти Иоанна Грозного» Толстого.
- gramophone: три пластинки без подписей (со звуком), три конверта («Борис Годунов»,
  «Опричник», «Купец Калашников»), рядом реальные 3D-пластинки, конверты и стопка либретто;
  взаимодействие открывает HTML-оверлей; игрок на слух и по словам
  узнаёт, что чья; пластинки раскладываются по конвертам. Без звука — текстовый режим.
- connect-pairs: портреты композиторов ↔ писателей (Мусоргский—Пушкин,
  Чайковский—Лажечников, Рубинштейн—Лермонтов); рамки двух цветов; названия узнаются
  по обложкам, висящим в зале с картинами (Васнецов «Купец Калашников», обложка
  Лермонтова, обложка нот Рубинштейна).
- finale «Редакционная записка»: игрок раскладывает открытые картины по 3–6 темам
  (без штрафа), затем на стене проявляется нейтральная статистика (сколько картин о
  насилии/трагедии против государственных свершений), затем открытый вопрос
  «Почему эпоха великих реформ рисовала именно такого Грозного?» — не оценивается.

## 3D-сцена и управление

- `src/world` содержит renderer, построение залов из `halls.json`, картины, пюпитры, двери,
  управление, взаимодействия, менеджер миров и запасной список залов.
- В каталоге заданий «рядом висит книга/пластинки» означает настоящие 3D-объекты в зале;
  взаимодействие с ними открывает обычный HTML-оверлей.
- Запасной список залов используется при недоступном WebGL и сохраняет ту же игровую логику.

## Интеграция заданий в 3D

### Объекты заданий

- В `halls.json` для каждого игрового объекта задаётся запись `taskObjects` с полями:
  `{id, taskId, kind, position: [x, y, z], rotationY, label}`. `kind` — имя функции-строителя
  из `/src/world/props/task-objects/`; `label` используется как HTML-подсказка при наведении и
  не содержит повелительных слов.
- Объект задания имеет коллайдер, подсветку при наведении и `userData.name`. Его состояние —
  `idle` или `solved`. При решении вид объекта меняется: зажигается латунная лампа, закрывается
  крышка либо появляется печать — по типу предмета.

### Взаимодействие и оверлеи

- `interaction.ts` вызывает `onInteract({type, id})`. Для `taskObject` открывается оверлей
  задания; для картины открывается «Разворот», для пюпитра — книга.
- Общий компонент `/src/ui/overlay.ts` обслуживает задания, «Разворот», книгу и меню. При
  открытии он снимает pointer lock, очищает набор нажатых клавиш, отключает игровые горячие
  клавиши и переводит фокус в оверлей с `aria-modal` и focus trap.
- Закрытие срабатывает по Esc, латунной кнопке-крестику или клику по затемнению. Если до открытия
  был pointer lock, при закрытии он возвращается; фокус также возвращается к исходному элементу.
- Фон оверлея непрозрачен либо затемнён не менее чем на 90%. Весь текст — HTML размером не менее
  18 px с контрастом не ниже 7:1; под текстом нет blur/backdrop-filter, текст не масштабируется
  через `transform: scale`. Используются локальные шрифты.

### Модули заданий и завершение

- Каждое задание — модуль в `/src/tasks` с интерфейсом
  `Task { mount(el, cfg, api: { attempt(ok), solve(), useHint(n) }); destroy() }`.
  Конфигурация находится в `tasks.json`, подсказки — в `hints.json`, очки считает
  `engine/scoring`.
- В UI запрещены слова-указания «нажми», «кликни», «пойди», «прочитай», «перетащи», «выбери».
  Обратная связь передаётся через мир: щелчок, свет или анимацию.
- После решения оверлей показывает короткую анимацию результата и закрывается, затем 3D-объект
  переходит в состояние `solved`. Когда решены все задания зала, анимированно открывается дверь
  в следующий зал.
- В запасном режиме без WebGL те же оверлеи открываются кнопками из списка залов.
