# Сборка и размещение

## Локальная сборка

Требуются Node.js 20 и npm. Из корня проекта:

```sh
npm ci
npm run build
```

Готовая статическая игра находится в `dist/`. По умолчанию `vite.config.ts` собирает пути от `/`, что подходит для сайта в корне домена. Для публикации в подпапке задайте базовый URL во время сборки, например:

```sh
VITE_BASE=/igra/ npm run build
```

Значение `VITE_BASE` читается `vite.config.ts` и должно совпадать с публичной подпапкой, включая начальный и конечный `/`.

## Hostland по FTP

1. Соберите приложение для корня домена либо нужной подпапки.
2. Передайте **содержимое** `dist/` в соответствующий каталог сайта на Hostland.
3. Передайте каталог `api/` рядом с `index.html`, чтобы адрес endpoint был `https://ваш-домен/api/leaderboard.php`.
4. Дайте PHP-процессу право создавать и изменять `api/leaderboard.json`. Обычно достаточно права на запись каталога `api/` для пользователя PHP; не делайте файл публично доступным для изменения через FTP-пользователя сайта.
5. В панели Hostland выберите поддерживаемую версию PHP 8. Репозиторий данных должен оставаться в каталоге API; `api/leaderboard.json` создаётся endpoint-ом при первом запросе.
6. Проверьте страницу по HTTPS, загрузку 3D-сцены и картин, затем откройте `https://ваш-домен/api/leaderboard.php`: ответ должен быть JSON с `records`. Отправьте тестовый результат через игру и убедитесь, что он отображается на стартовом экране и после финала.

GitHub Actions может выполнить те же шаги загрузки. Добавьте secrets `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`, `FTP_SERVER_DIR`; затем запустите workflow `Deploy to Hostland` вручную или отправьте тег `v*`. Workflow загружает собранный `dist/` и `api/` в корень из `FTP_SERVER_DIR`.

## GitHub Pages

Pages обслуживает только статические файлы и не запускает PHP. Если endpoint недоступен, игра показывает локальную книгу рекордов из `localStorage` с отметкой «Локальный рекорд». Для общей таблицы используйте Hostland или другой PHP-хостинг.
